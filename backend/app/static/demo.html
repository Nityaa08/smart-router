Smart Router: every prompt gets a lane.

An OpenAI-compatible LLM gateway. Hand-written rules score each prompt in under a millisecond and switch it to the cheapest model tier that fits, with fallback to the next tier and a cost log against GPT-4o.

Python · FastAPI
Problem
Apps send every prompt to one expensive model, even “what is 2+2?”. Most prompts don’t need it.
What I built
A drop-in OpenAI-compatible gateway that scores each prompt with rules in under 1 ms, picks the cheapest tier that fits, falls back if a provider fails, and logs the cost.
Proof
23 of 24 hand-labelled prompts routed to the right tier, 138 tests, CI on every push. The one miss is shown, not hidden.

How it works request path

The gateway speaks the OpenAI chat format, so an app only changes its base URL. No LLM is used to classify: the score comes from length, keywords, code, multi-step and math patterns.

Drop-in APIPOST /v1/chat/completions, plus X-Router-Tier and X-Router-Model headers.
ExplainableEvery decision traces back to the rules in the log above; /v1/route/explain returns them.
ResilientA failing provider escalates to the next tier, for normal and streamed requests.
TestedUnit tests with fake providers cover routing, fallback, streaming, cache, auth and limits.
